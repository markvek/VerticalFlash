# Creative brief

Use this guide before choosing footage and generating storyboard options. Read `library_list` and `project_list` first so questions reflect material that exists.

Capture these fields in the conversation or a project note in the agent's workspace. The current connector has no `brief_save` tool; do not claim this note was saved in VerticalFlash.

| Decision | Record |
|---|---|
| Goal and audience | What the viewer should understand or do, and who they are |
| Starting material | Existing master/project IDs or exact library filenames |
| Format and tone | Demonstration, explanation, testimonial, montage; desired delivery |
| Length | Target seconds and any acceptable tolerance |
| Hook and ending | Opening promise/question and the final payoff or CTA |
| Audio and text | Preserve speech, use a music track, or silence; on-screen text preference |
| B-roll | Allowed coverage, moments to keep the speaker visible, source restrictions |
| Budget and review | Existing spend limits and which creative stages the user wants to review |

Recommend an angle based on available footage. If a decision matters, offer a small number of concrete alternatives and explain how the video changes. Reuse choices the user already made.

Example brief: “30-second product explanation for first-time buyers. Lead with the working demo, then one practical benefit and a concise CTA. Conversational tone, original speech, library B-roll over the feature explanation, speaker visible for the ending. Review storyboard options before cutting.”

The first connector workflow is source footage → transcript → storyboard → accepted edit. Prompt, music-first, inspiration, and iteration projects exist in the app, but their creation is not exposed through this connector. Use the relevant app page when that is the user's chosen starting mode. Do not invent MCP tools for those modes.
